## 0. 一句话

把「点一下 → 90 秒 → 出一个成品，好不好只能认命」，改成
**「先出剧本大纲（3 秒、几乎不花钱）→ 经纪拖拽/增删/AI 再检查 → 满意了才渲染」**。

---

## 1. 为什么是两阶段

| | 现在 | Studio |
|---|---|---|
| 经纪的控制权 | **零**。生成完就是成品 | 大纲阶段可以反复改 |
| 最贵的一步（TTS，8–11 次调用） | 在经纪**还没看到剧本**时就烧掉 | **挪到确认之后** |
| 改一个字 | 重新生成整个 tour（100 积分） | 改大纲不花钱，只有渲染花 |
| 失败成本 | 100 积分 + 90 秒 | 大纲重来 ≈ 0 |

**成本直接减半** —— 现在每次生成都在为一个经纪可能根本不想要的剧本付 TTS 费。

## 2. ⭐ 素材库由**数据**决定，不是写死的清单

这是整个设计里最重要的一条结构性约束。

大纲里能放什么 beat，**取决于这个项目和这个客户真实拥有什么数据**：

| Beat | 解锁条件（全部是 DB 查询，不是配置） |
|---|---|
| **地理套利**（周边区域对比） | 该区有 ≥3 个成交量 ≥500 笔的地理邻居（PostGIS `ST_DWithin`） |
| **流动性证据** | 区域 `transaction_count` ≥ 阈值 |
| **真实成交对比** | `dld_transactions` 里有可比成交 |
| **通勤 / 你的一天** | 经纪填了 ≥1 个客户的真实目的地 |
| **地铁** | 半径内**真的**有 `metro_station`，且名字**不是**阿拉伯语 |
| **学区** | 有学校 POI **且** `has_children = true` |
| **户型匹配** | `project_unit_types` 有 `features` |
| **ROI / 数字** | 区域有 `capital_growth_pct` **且** `rental_yield_pct`（`get_dubai_area_metrics`） |
| **它的短板 + 反驳** | 至少有一个维度上该项目输给参照组 |

> 🔴 **没数据的 beat 根本不出现在素材库里，经纪想加也加不了。**
>
> 这样「适合的户型（其实是最便宜的 8 个）」「地铁是 11 公里外的药房」「每份 tour 都是 73% 增值」
> 那类 bug 就变得**结构上不可能再发生** —— 而不是靠在 prompt 里求 AI 别撒谎。
>
> **能力边界由数据定义，不由文案定义。** 这是本次所有修复里最该被保留的一条原则。

灰掉的 beat 要**说明为什么**（「这个项目 2km 内没有带评级的学校」），而不是静默消失 ——
经纪需要知道产品的边界在哪。

## 3. 新的 tour 结构：把「做梦」和「尽调」拆开

> **Jiang, Gao & Huang（JCR 2014，用真实房产做的眼动实验）：观众在构建叙事时，
> 切换视角会降低他对房子的评价。**

而现在每一幕正是：低空绕楼（第一人称）→ 俯视数据卡（上帝视角）→ ROI 数字（分析视角）。
**我们在客户刚开始「想象自己住在这里」的那一刻，把他一脚踹出去看报表。**

```
Ⅰ 做梦（第一人称 · 低空 · 不出现任何百分比）
   ├─ 你的坐标        城市高空落到这块地。先让他看见自己在哪儿
   ├─ ⭐ 你的通勤     经纪填了太太的公司、孩子的学校 → 镜头真的沿路飞过去，报真实时间
   ├─ 你的周末        海滩/公园/商场（步行 15 分钟内才讲）
   └─ 你的家          进户型。女佣房、洗衣房、开放厨房 —— 对着他家的情况逐条讲

   ══════ 明确的模式切换（视觉上也要切）══════

Ⅱ 尽调（俯视 · 数据 · 敢说缺点）
   ├─ ⭐ 地理套利     镜头拉高，六个邻居区域同时亮起，涨幅浮在各自地块上
   ├─ 这个价值不值    项目单价 vs 区域中位；真实 DLD 成交背书；**净回报**（扣物业费）
   └─ ⚠️ 它的短板     主动说出输在哪 —— **然后立刻反驳**

Ⅲ 行动
   └─ 下一步          CTA 不在这里第一次出现（它在情绪高点已经飘出来过）
```

### 3.1 ⭐「你的通勤」—— 最狠的一拍，也是当前最大的缺口

**~半个房子的价值是位置（土地占 32–51%，Davis & Palumbo, JUE），而 ~100% 的 tour 是建筑。**
它绕着楼转了三圈，从没带客户去过地铁站。

- **Zoopla 上线通勤圈搜索 → 预约看房转化涨 3 倍**（量的是真实预约，不是点击）
- **Stutzer & Frey（2008）：单程 1 小时通勤的人，需要多 40% 收入**才能达到不通勤者的满意度。
  而市场**从不补偿**他们。人们**高估**通勤换来的钱和面积，**低估**失去的东西。
  → **这是一个正好长在我们用户身上的决策 bug，而没有一个迪拜经纪在说它。**
- 迪拜地铁真实溢价：**距站 701–900m 处峰值 ~+13% 住宅**（*Journal of Transport and Land Use*，同行评审）。
  ⚠️ **不是**市面上流传的「18–25%」（查无实据）。

### 3.2 ⭐「它的短板」—— 诚实必须**带反驳**，否则会害你

> **Allen 的元分析：说了缺点却不反驳它，比什么都不说更糟。**

有效的机制不是「坦诚」，是**接种（inoculation）**：你在给客户打疫苗，
让他**免疫下一个经纪要说的话**（Banas & Rains 元分析 g≈0.41，且**不受精细加工程度调节** ——
高卷入的买房场景照样有效）。

⚠️ **别用「瑕疵效应」来论证** —— 它是个低卷入效应，在高卷入下**会反转**，而买房是卷入度最高的消费。

**范式（用真实数据）：**

> 「说实话，JVC **不是**这一带涨得最快的。隔壁 JVT 涨了 15%，Arjan 13.5%，都比这里猛。
>
> **但是** —— JVC 一年成交 **14,790 笔**，是它们的三到四倍。你想出手的时候，这里永远有人接盘。
> 涨得快而没人买，那个数字是纸上的。
>
> 如果你要的是三年翻倍然后跑，我诚实地说：隔壁 JVT 更适合你。
> 如果你要的是拿得住、租得掉、卖得出 —— 那是这里。」

### 3.3 地理套利（你点名要的）

投资客真正想知道的不是「这个项目涨多少」，而是**「我为什么该买这里，而不是走路 5 分钟外的那个区」**。
**这是地图产品能做、而 PDF 楼书和视频永远做不到的事。**

数据已经全在库里（PostGIS 邻居 + `get_dubai_area_metrics`，实测）：

| 区域 | 距离 | 涨幅 | 回报 | 单价/㎡ | 成交量 |
|---|---|---|---|---|---|
| **JVC**（目标） | — | 8.5% | **6.69%** | 16,084 | **14,790** |
| JVT | 0.2km | **15.0%** | 5.90% | 17,537 | 5,251 |
| Arjan | 0.1km | **13.5%** | 6.38% | 16,482 | 3,885 |
| Motor City | 0.5km | **0.0%** | 4.07% | **20,236** | 4,855 |

> 0.5 公里外的 Motor City：单价比 JVC **贵 26%**，涨幅 **0%**，回报只有 4.07%。
> **同样的地段，你多付四分之一，换来一半的回报。**

⚠️ **必须按成交量过滤邻居**（实测 Al Barsha South 2 只有 **7 笔**成交 —— 拿它做对比是在用噪音说话）。

### 3.4 还没用上的两张牌

1. **期房溢价 vs 现房**（Property Monitor）：42 个社区里 **14 个溢价 >30%**，
   顶到 **85%（Motor City）**、73%（Sports City）。
   **没有一个卖期房的人会告诉买家这个数。Luna 说了，然后解释它什么时候仍然值 ——
   她就成了这个买家遇到的唯一可信的声音。**
2. **净回报 vs 毛回报**：所有人报毛的。迪拜物业费中位 **AED 17/sqft/年**，
   **直接吃掉约 1 个百分点**（Downtown / 品牌公寓 1.5–2 个点）。
   报净的、并把被吃掉的那一截**画出来**，本身就是一次可信度展示。

### Luna 的意见**不是硬编码**（owner 明确要求）

| 层 | 干什么 | 成本 |
|---|---|---|
| **规则** | 结构性硬伤：投资客没有流动性那一拍；某个项目只有到达没有数字；总时长超标；「短板」那一拍**没有反驳** | 0 |
| **LLM** | 基于**你刚改完的大纲** + 客户画像给个性化意见 | 1 次 Flash 调用 |

**你改了大纲，它的话就跟着变** —— 不会是同一套。
（和客户画像 coach 的分工同构：规则查硬缺失，LLM 出个性化洞察。）

## 5. 运镜：从 LLM 手里拿走

现在的 prompt 要求模型输出每个镜头的 `{ center, zoom, pitch, bearing, duration, easing }`。
**但模型不是摄影师。** 它不知道 zoom 16 能看见什么、pitch 60 好不好看、
相距 5 公里的两个项目之间该怎么转场。**它在猜数字，所以镜头就在乱飞。**

> 和报告那边**完全同构的错误**：**AI 在干它不擅长的机械活。**
> LLM 应该说「这一拍要讲地铁很近」，**由代码决定**「从楼顶 55° 推向地铁站，画连线，2.4 秒 easeInOut」。

### 镜头语法（代码生成，硬规则）

| 规则 | 做法 | 依据 |
|---|---|---|
| 飞行曲线 | `curve = 1.42`，`speed = 1.2`（**屏幕/秒**，不是公里/秒） | 1.42 **就是 van Wijk 的 ρ** —— 最优的「拉高→平移→落下」路径，数学上最优。MapLibre 的默认值就是它 |
| 飞多久 | **硬上限 4 秒。超了就 CUT，不要飞** | Cesium 给**每一次**飞行都设 3 秒硬顶。30km 飞过沙漠 = 6–8 秒虚无，Tversky：它**什么也没教给观众** |
| 动 or 切 | **空间关系本身是信息 → 动。新话题 → 切** | Bederson：动画帮助重建空间认知。Tversky：动画对**讲道理**毫无帮助。<br>**运镜是给「在哪里」用的，永远不要用运镜来讲数据。** |
| 缓动 | **所有属性同一条曲线，经纬度尤其** | ⚠️ **手搓相机最常见的 bug**：经纬度用不同曲线缓动，**会把地面轨迹扭曲成一条你从没设计过的弧线** —— 看起来就像镜头在飘（Google Earth Studio 官方警告） |
| 节奏 | ~~每幕 8s/12s/10s~~ → **长镜头聚在开头，快节奏聚在中段，结尾一次长释放** | Cutting（*Psych Science*）：电影的镜头长度序列呈 **1/f 粉红噪声**，和人类注意力同谱。**恒定节拍是白噪声 —— 那正是它「像软件不像电影」的原因** |
| 旋转 | 飞行途中**不要同时转 180°** | van Wijk 的最优路径只管 2D。bearing 是硬贴上去的线性插值 → 变成一个和飞行竞争的运动 |

**已落地（2026-07-12）**：`tour-generator.clampCinematography()` 在代码层硬 clamp
（≤4000ms、orbit ≤120°、`property_card`/`roi_card` 一律 `at_ms=0`）——
**不指望 prompt，LLM 会违反，代码不会。**

## 6. 投资客 vs 自住家庭：两个 tour

**不是**「投资客看数字、家庭看感觉」（那是民间传说）。
真正的原因是 **Escalas：分析式框架会邀请客户来审视你 —— 所以只有当你的数字真的赢，才该用它。**

| | 投资客 | 自住家庭 |
|---|---|---|
| **第一个数字**（= 他的参照点） | 区域中位单价（让单元显得便宜） | **他现在的房租**（让月供显得合理） |
| 戏剧化的时间 | 5 年退出、回本年限 | **一个周二早晨** |
| 飞去哪里 | 地铁站、DIFC 天际线 | **他太太的公司、他孩子的学校** |
| 要反驳的质疑 | 交付风险、出手流动性、物业费吞掉回报 | 买得起吗、通勤、学校 |
| CTA | 「看付款计划」 | 「约个时间去看房」 |

> **锚定是最强的杠杆**：无论你先给出哪个数字，它都会成为客户的参照点 —— 这是房产里复现得最好的效应，
> 而且**对声称自己不受影响的专业人士照样有效**。
> **用精确数字，不要整数**：`AED 2,847,000` 的锚定力强于 `AED 2,850,000`，且换来更温和的还价。

## 7. 三件小事，回报极高

1. **CTA 不要放在结尾。** 结尾 CTA 拿到 **6%** 的线索；**内容中途**的拿到 **47–93%**（HubSpot 一方数据）。
   在**情绪高点**触发 —— 而 telemetry **已经能检测到那个点**（`property_dwell`）。
2. **客户一看完，立刻通知经纪** —— **全场回报最高的一件事，而且它根本不在 tour 里**。
   一小时内联系，资格转化率 **7 倍**。
   而现在 `lt_engagement_events` 在 `luna-tour/` 之外**零读取**，`client_id` **从不设置** ——
   「客户行为回传给你」这个核心卖点，**目前止步于一个可折叠面板**。
3. **别再说「3D 看房能多卖 9%」** —— 厂商自己出的数，两个独立大样本研究（n≈43k、n=75k）
   都发现**对成交价没有影响**。真实的好处是**卖得更快**（34→19 天）和**实地看房 +21%**，
   而且**只在信息稀缺、渗透率低的市场**有效 —— 也就是**期房、远程买家、非核心区**。
   **那正是 Pinzos。** 这是一个更强、而且经得起查的论据。

## 9. 实施顺序

| | | 为什么先做它 |
|---|---|---|
| **P0** | 堵匿名白嫖 | `currentAgentId()` 无 token 时 fallback 到 demo 账号，而配额门是 `if(isLoggedIn)` → **匿名 = 跳过配额**。开放互联网可以无限烧 Gemini + TTS。**钱在漏。** |
| **P0** | 接通 CRM + **看完即时通知** | 核心卖点目前是假的，而这是**回报最高**的一改（7×）。 |
| **P1** | `tour-generator` 加真 `responseSchema` | 它**连 responseSchema 都没有**（只有 `responseMimeType` + prompt 里的散文描述）→ 字段可以被自由丢弃/改名，得靠一个修复重试循环擦屁股。全字段 `required` + 允许 `null`，加 `thinkingLevel:'low'`。**重试循环可以整个删掉，成本减半。** |
| **P1** | TTS 模型 ID（同一个过期坑） | `tts.ts` 还挂着 2.5 系列（**最早 2026-10-16 关停**），而 `resolvedModel` 缓存第一个能用的 → 产品可能已经在静默地骑一个将死的 preview。 |
| **P2** | **Studio**（两阶段 + 素材库 + 拖拽） | 让经纪能控制产出，顺带把 TTS 挪到确认之后。 |
| **P2** | Journey 拍 + 地理套利 + 镜头语法 | 这才是让人**产生购买冲动**的部分。 |
| **P3** | OG image | 一个**唯一分发渠道就是往 WhatsApp 粘链接**的产品，**分享出去是空白预览**（7/7 session 的 `og_image_url` 都是 NULL）。 |
