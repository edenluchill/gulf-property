# 手机版地图右上 panel:两个方案对比(2026-07-11)

## 背景 / 问题

现在手机(390px 宽)地图上的浮层:

| 元素 | 尺寸 | 占比 |
|---|---|---|
| 右上控制卡(口径 + 5 指标 + 5 POI + 指标名) | 184 × ~120px | **横向 47%** |
| 右侧工具卡(底图/3D/测距/项目) | 60 × ~190px | 横向 15% |
| 左侧筛选卡(5 项 + 清除) | 62 × ~300px | 横向 16% |
| 底部搜索 dock | 全宽 - 68px | 高 ~44px |

用户反馈:
1. 右上那张卡**横着吃掉近一半屏幕、高 120px**,像个 header bar,挡太多;
2. 但客户**必须能直接点**(切指标/口径不该多绕一层);
3. 左侧筛选按钮**比 panel 里的图标大**,要统一成 panel 的规格;
4. 指北针孤零零挂在左下角,想**并进左上筛选卡**。

---

## 已经定了、不用选的部分(两个方案都会做)

- 左侧筛选按钮 → 缩到 panel 同款 **28×28**,卡宽 62 → **36px**
- **指北针并进左侧筛选卡**(卡里最上面一颗按钮),左下角腾空
- 选中的筛选值仍要看得见(见下面「筛选值怎么显示」)

### 筛选值怎么显示(按钮缩到 28px 后放不下文字了)

按钮里塞不下 `1M–2M` 这种值,改成:**卡片下方挂一条「已选」摘要**,宽度固定、超长截断、点 × 一键清空:

```
┌────┐
│ 🧭 │  ← 指北针(并进来了)
├────┤
│ 🏷 │  ← 价格(选中=主色填充)
│ 🛏 │  ← 卧室(选中=主色填充)
│ 🔨 │  ← 状态
│ 📅 │  ← 交房
│ 🏢 │  ← 开发商
└────┘
┌─────────────────┐
│ 2+ · 1M–2M    ✕ │  ← 已选摘要(只在有筛选时出现)
└─────────────────┘
```

## 方案 A:并进右侧竖轨(**推荐**)

右上那张卡**整个拆掉**,内容并进右墙一条 **44px 宽**的竖轨,和工具卡合成一条。每颗仍是直接点,不多一次点击。

```
现在(184px 宽的卡压在右上角)              方案 A(右墙一条 44px 竖轨)
┌───────────────────────────────┐        ┌───────────────────────────────┐
│┌──┐      ┌──────────────────┐ │        │┌──┐                      ┌──┐ │
││🧭│      │  全   期房   现房 │ │        ││🧭│                      │期│ │ ← 口径(点一下循环/弹出)
│├──┤      ├──────────────────┤ │        │├──┤                      ├──┤ │
││🏷│      │  $   $   ↗   ▥  %│ │        ││🏷│                      │$ │ │ ← 指标 5 颗
││🛏│      ├──────────────────┤ │        ││🛏│                      │$ │ │
││🔨│      │  🚇  ✚  🎓  🛒  📍│ │        ││🔨│                      │↗ │ │
││📅│      ├──────────────────┤ │        ││📅│                      │▥ │ │
││🏢│      │    $ 中位数房价    │ │        ││🏢│                      │% │ │
│└──┘      └──────────────────┘ │        │└──┘                      ├──┤ │
│                               │        │                          │📍│ │ ← POI(开面板)
│                               │        │                          ├──┤ │
│        地图被压掉一大块        │        │       地图整片干净         │🌐│ │ ← 底图
│                               │        │                          │📦│ │ ← 3D
│                               │        │                          │📐│ │ ← 测距
│                               │        │                          │👁│ │ ← 项目卡显隐
│                               │        │                          ├──┤ │
│                               │        │                          │成交量│ ← 当前指标名(轨底)
└───────────────────────────────┘        └───────────────────────────────┘
   横向吃 184px(47%)                      横向吃 44px(11%)
```

**好处**
- 横向从 184px → 44px,中间彻底空出来,地图看得最全
- 全部控件收敛成「一条右墙」,视觉上只剩一个东西,不再是三张卡各占一角
- 每颗仍是一次点击直接生效(口径除外,见下)

**代价**
- 竖轨会比较长(约 11 颗按钮 ≈ 380px 高),几乎贯穿右侧;小屏(iPhone SE 667px 高)会显得满
- 口径(全部/期房/现房)是三选一,竖轨里只能给一颗按钮 → 要么点一下循环切换(全→期→现→全),要么点开一个小弹层选。比现在的三个 tab 多一步
- 指标名只能写在轨底,字更小

## 方案 B:panel 瘦身、不搬家

右上仍是一张卡,但砍掉一行、缩小图标:

- **POI 那一行搬去工具卡**(变成一颗 📍 按钮,点开现有的 POI 面板)
- 指标图标 28 → **24px**,口径 tab 字号缩小
- 卡从 **184 × 120** → 约 **150 × 80**


**好处**
- 改动小、风险低;口径仍是三个 tab 一眼可选可点(A 方案要多一步)
- 指标 5 颗仍横排,肌肉记忆不变
- POI 本来就不是高频操作,收成一颗按钮很合理

**代价**
- 右上角**依然有一块**(150px ≈ 屏宽 38%),只是矮了、窄了,没有 A 那么彻底
- 工具卡会变长一颗(5 颗按钮)

## 我的建议

**选 A**,如果你的目标是「地图为主角、UI 全部退到墙上」——这也是 Google/Apple 地图移动端的做法(所有控件贴右墙一条,中间不放东西)。口径多一步点击是可接受的代价:大多数客户全程用「全部」口径,只有内行才会切期房/现房。

**选 B**,如果你觉得口径三个 tab 必须常显、且不想冒改动风险。它是稳妥的一半改进。

> 两个方案都不动 panel 里的指标项(median price / sqft 都保留),因为你说过不要再删东西。

---

## 附:两个方案共同的验收标准

- 中/英文切换后**所有按钮尺寸不变**(实测宽度必须完全相等)
- 手机 390 / pad 1180 / 桌面 1440 三档截图,pad 与桌面布局不受影响
- 真机手势(非 force click)能点到每一个按钮 —— 上一轮踩过坑:整合卡的 `backdrop-blur` 会自成层叠上下文,卡不给 z-index 就会被关闭下拉的透明遮罩盖住,导致**筛选选项点了没反应**
