扣款失败被当成「从没订阅过」

起因是「修 starter 档」。查下来 Starter 那三个 0 是设计不是 bug —— 真正的缺陷在全站 18 处订阅判断里，而且它已经伤过唯一一个真付过钱的客户。

2026-08-24 · 生产库实查 + 代码审计 · 已修复并部署

1. 先否掉原假设：Starter 的三个 0 是设计

之前的报告把这个当成事故：

Starter ($25/月) limits：
  credits_month:   200
  reports_month:   10
  brochures_month: 5
  sessions_month:   0   ← 不能建 tour
  live_tours_month: 0   ← 不能带看
  call_units_month: 0   ← 不能用语音

但定价页（PricingPage.tsx + 生产截图核对）里 Starter 卖的从来就不是这三样：

Starter $25 明写包含Pro $49 才有
地图与市场数据不限时（260+ 区域 DLD 成交/租金/收益率）实时海外带看
客户 CRM · 档案 / 热度评分 / 时间线应用内语音
买家意向报告Luna AI 智能导览
AI 楼书解析 · Sales Offer 报价单 · 品牌报告页带看意向报告 · Lead 优先推送
结论

三个 0 = Pro 的差异化，是有意的。把它们改成非 0 等于取消 Pro 的存在理由。 不改。

2. 真正的缺陷：past_due 全站被判成「没订阅」

全站 18 处订阅判断写的是 status IN ('active','trialing')， past_due 不在里面。

past_due 的语义是：卡扣失败，但 Stripe 仍在按 dunning 计划重试 （默认约 2 周，重试完才转 unpaid / canceled）。 处在这个状态的人是正在试图付钱的客户。

而我们的判定后果：

位置后果
mapMeter.ts地图当场锁死，且返回 requiresPlan: true → 前端提示他「去选套餐」
credits.ts planFor()掉回 explore（0 积分）→ 所有付费功能失效
requireUploader.ts楼书上传权被没收
freeTrial.ts「已有订阅」判定失效 → 付费用户可以去领免费试用
billing.ts teamSubOf()团队席位管理失效
PricingPage.tsxhasPlan=false → 给付费客户看「7 天免费试用」
agents.ts / adminBizQueries后台把付费客户显示成「从没付费」

这正是 RichKey 那一单的死法

日期事
07-10 11:41注册后 3 分 25 秒付钱（Starter $25）
07-18已付费状态下去点了「免费试用」 ← freeTrial.ts 没拦
07-27撞地图额度墙 ×2 → 立刻去看定价页
07-28扣款失败 → past_due → 全站判成免费用户
之后反复看定价页十几次，再没买过

我们把唯一一个真付过钱的客户，在他卡扣失败的当天，锁在了门外， 还提示他「去选套餐」。

而且这个坑记过一次

记忆条 subscription-past-due-hidden 早就写过「查订阅必带 past_due」。 之后仍然散点复发了 11 处后端 + 7 处前端。 写在记忆里不等于收口 —— 只有单一真源能真正防住。

3. 修法：收口，不逐个打补丁

新建两个同名单一真源文件：

backend/src/lib/subscriptionStatus.ts
  ENTITLED_STATUSES = ['active','trialing','past_due']
  ENTITLED_SQL      = "('active','trialing','past_due')"   // 直接插进 SQL
  isEntitled(status)

frontend/src/lib/subscriptionStatus.ts
  isEntitled(status)        // 还有没有权益
  needsPaymentFix(status)   // 钱出问题了，UI 要显示「换卡」
  • 后端 11 处 SQL 改用 ${ENTITLED_SQL}
  • 前端 7 处 改用 isEntitled()
  • 定价页新增 past_due 专用 CTA：「更新支付方式」→ Stripe 客户门户， 优先级排在试用/订阅之前。给一个已经在付钱的人看「免费试用」，等于告诉他他不是客户。
  • 新 i18n 键 updatePaymentMethod × 5 语言，i18n-key-check 通过（2261 键）

有意不含的两个状态

状态为什么不给权益
unpaidStripe 已经重试完并放弃了。到这一步才该真正断权益
incomplete首次付款从没成功过（3DS 没走完等），压根没成为过客户

4. 一个 tsc 抓不出来的坑

差点栽进去

${ENTITLED_SQL} 只在模板字符串（反引号）里才会插值。 如果那条 SQL 是用单引号写的，${...} 会静默变成字面量， 查询条件变成 status IN ${ENTITLED_SQL} —— 语法错误要到运行时才炸， tsc 完全查不出来。

所以 11 处替换后逐个核对了包裹引号类型，并在生产容器里真跑了一遍那条 SQL 验证插值结果。

ENTITLED_SQL      = ('active','trialing','past_due')
isEntitled(past_due) = true
