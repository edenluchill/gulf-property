# 「这么多注册却不去试用」的真相 + 订阅后台改造 —— 2026-07-28

起因：owner 看着后台「未订阅账户 (36)」问「能查一下为什么这么多注册但是没有去试用吗」。

---

## 0. 结论：这个问题的前提是错的

**真经纪里「从没试用」的只有 1 个人。**

后台那 36 个「未订阅经纪」是个假象 —— 它把六种完全不同的人塞进了同一个标签。

| 真实身份 | 人数 | 该怎么看 |
|---|---|---|
| 经纪 · **试用过期了** | 13 | 🔴 真问题：试了没留下 = **留存**，不是获客 |
| 经纪 · 从没试用 | **1** | 几乎不存在 |
| 开发商 · 试用过期 | 3 | 同上 |
| **买家** | 9 | 买家本来就免费，不订阅是设计如此 |
| **没选过角色** | 10 | 连试用入口都摸不到（见 §2） |
| **扣款失败的付费客户** | 1 | 🔴 见 §3 |

### 为什么会显示成「36 个经纪」

`ensureAgent()` 在**每次登录**时给任何登录用户插一行 `lt_agents`，而 `lt_agents.role`
这一列的**默认值就是 `'agent'`**。后台读的正是这一列 → 买家、开发商、没选角色的人
一律被打上「经纪人」标签。

真正的角色在 `user_profiles.role`（试用接口读的也是它）。两个来源，后台读错了那个。

**已修**：后台改读 `COALESCE(user_profiles.role, 'unset')`。

### 真实的经纪漏斗（40 个真经纪）

```
40 个经纪
├─ 26 有生效订阅  ← 其中 25 个是**免费试用中**，不是付费
├─ 13 试用过期流失
└─  1 从没试用
```

**试用 → 付费的转化 = 0。** 全站唯一的外部真付费客户见下。

所以要问的不是「为什么不来试用」，而是**「41 个人在试用，为什么一个都没留下」**。

## 1. 谁在没订阅的情况下用地图

owner 问：「他们选了经纪没买 plan 也能用地图？」

**不能 —— 经纪的门早就是硬锁**（`mapMeter.meter()`：未订阅经纪 `exhausted: true`，
不给每日额度）。抽查 `slavynchuk94` 那 13 次成功的地图请求，全部发生在试用期内（07-24，
试用 07-18→07-25），没有越权。

**但有一个洞**：`agentNeedsPlan` 的豁免分支写的是「买家 / **未选角色** / 已订阅经纪」——
没选过角色的人和买家走同一条路 → **无限免费用地图**。实测 10 个账号处于这个状态，
其中有人几百次调用、天天还在用。而且这批人 `/trial/start` 会直接 403 `not_agent`
（那个接口读 `user_profiles.role`）—— **既不付费，也永远转化不了**。

**已修**：门改成三态，「没选角色」按匿名额度计量（10 分钟/天），不再全免。
给额度而不是直接锁 —— 他们里既可能是没点完引导的买家，也可能是经纪；10 分钟够看明白
这是什么产品，用完的提示会把他推回去选角色。

买家仍然全免（他们就是免费那一侧，这是产品设计，没动）。

## 2. 🔴 全站唯一的外部付费客户，正在扣款失败

`slavynchuk94@gmail.com` 有一条 **`past_due`** 的 Stripe 订阅（07-10 开，账期到 08-17，
今天还在更新状态）—— 卡扣不动了。

而 `getSubscribers` 只 JOIN `status IN ('active','trialing')`，于是**他掉进了
「未订阅账户」列表**，和从没付过钱的人排在一起，后台给他的唯一操作是「赠 Pro 30 天」。

该做的是催他换卡，不是送他 30 天。

**已修**：`past_due` / `unpaid` / `incomplete` 一并纳入「有订阅」，红色「扣款失败」徽标 +
顶部单独一张统计卡 + 单独一个置顶分组。

## 3. 页面改造：不用再疯狂 scroll

owner：「人一多得疯狂 scroll 下面才能看到下一个 section」。

原来是两个平铺长列表（订阅客户 / 未订阅账户），80 个账户就是 80 行铺开，
底下还压着「楼书权限」「套餐变更记录」。

改成**按「要做什么」排序的可折叠分组**，每组默认只露 5 行：

```
🔴 扣款失败      ← 默认展开，催换卡
🔴 待审批        ← 默认展开
✅ 订阅客户      ← 默认展开
   试用过期了     ← 留存问题
   经纪·从没试用  ← 激活问题
   开发商 / 买家 / 没选角色  ← 默认收起
```

- 每组标题带人数徽标，超出部分写「展开其余 N 个」——**绝不静默截断**
- 空组直接不渲染
- 角色徽标按真实角色着色（买家=蓝 / 经纪=青 / 开发商=靛 / 没选角色=琥珀）
- 顶部统计卡换成有决策价值的：账户总数（注明含买家）/ 真付费 / 试用中 /
  **扣款失败** / **经纪未转化**（拆开显示从没试用 vs 试用过期）/ **没选角色**

买家账户现在也显示了（owner 要求），且标签正确。

## 4. 顺手修的两个性能问题（我自己造的）

1. 新加的 `last_seen` 我写成了逐行相关子查询 `lower(c.user_email) = lower(a.email)`。
   `idx_api_calls_email` 建在 **`user_email` 原值**上，套个 `lower()` 索引直接失效
   → 80 个账号 = 80 次全表扫，整个接口 **4.1s**。改成一次预聚合再 join → **1.5s**。
   （同一个坑 memory 里已有：`plpgsql-case-predicate-index-trap` / 手绘区表达式索引。）
2. 路由里 `getSubscribers()` 和 `getSubscriptionSummary()` 连着调，而后者内部**又跑了
   一遍同一条查询** —— 白等一倍。改成一次查询喂两份结果。

数据指向的下一步不是「获客」，是**试用期内的首次价值**：41 个人正在试用，转化 0。
