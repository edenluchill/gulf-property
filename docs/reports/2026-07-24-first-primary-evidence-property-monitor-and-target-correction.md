# 第一份一手证据：迪拜经纪/开发商到底在为什么工具付钱 + 目标客群修正

**日期**：2026-07-24

**性质**：一手证据 + 桌面查证 + 由此产生的目标客群修正（**含对本人前一轮建议的推翻**）

---

## 0. 一句话

> **一条微信问出的信息量 > 11 份桌面研究报告。**
> 最重要的发现：**Property Monitor —— 经纪公司已经在为「看 DLD 数据」付 AED 500+/月。**
> 这是三个月来第一次，「已经在流动的钱」与「本产品唯一被真实使用的功能」指向同一处。
> **目标客群修正：经纪公司 ↑ 第一 / 开发商 ↓ 第二（我上一轮的头号建议被部分推翻）。**

## 1. 一手证据原文（合伙人回答）

> **经纪公司主要付**
> - Property Monitor —— 看数据
> - Bayut、Property Finder —— 发布二手房源
>
> **开发商主要在付**
> 1. 传统的硬广，电视，大屏
> 2. CRM 系统
> 3. Bayut、Property Finder 流量广告
> 4. 自己建技术团队开发 3D 看房
>
> **补充**：「就我们现在做的，已经能让客户觉得比其他经纪人专了。」

**owner 在同一段对话中的判断（均正确，予以确认）：**
- 「我们现状是 0，0 个人付钱，即使推广了大概率还是 0，因为没搞到人家痛点」
- 「核心还是找出哪怕一个人真的能付钱的功能，然后再推广」
- 「如果靠卖 lead，那其实就是跟 Property Finder 打擂台，把流量从他们那引过来才有赚钱可能」
- C 端三条否决理由：没有买家信息 / 买家市场被战争腰斩 / 时间太长没钱耗不起

## 2. Property Monitor 查证结果

| 项 | 内容 |
|---|---|
| 是什么 | UAE 房产市场情报平台，**核心 = DLD 成交数据 + 自动估值 AVM** |
| 产品线 | PMiQ（市场情报）· valCheck（AVM）· valu'd（消费者估值）· DPI（价格指数）· valFlow（测量师工作流） |
| 出身 | 2014 年由 **Cavendish Maxwell**（RICS 持牌测量师行）创立 |
| **归属** | **2025-04 被 Dubizzle 集团收购**（Bayut 母公司） |
| **价格** | **AED 500+/月起，面向经纪公司** |
| 对比 | **REIDIN AED 2,000+/月**（机构级） |
| 免费替代 | Dubai REST（仅法律核验）· Dubai Pulse（原始 DLD，需编程）· 门户（仅挂牌价，非成交价） |
| 客户 | 银行、测量师、开发商、投资人、经纪公司 |

**换算**：AED 500 ≈ **$136/月**；AED 2,000 ≈ **$545/月**

## 3. 这条证据让什么变强了

### 3.1 买家是「经纪公司」，不是「经纪个人」

| | 现状 | 证据指向 |
|---|---|---|
| 一直在卖 | 个人经纪 $49/月 | **74 注册 : 0 付费** |
| **应该卖** | **经纪公司** | 合伙人原话「**经纪公司**主要付 Property Monitor」 |
| Agency 计划 $699 | **从未被尝试销售过一次** | 这才是唯一有预算的线 |

### 3.2 定价锚点（首次有真实参照）

> 经纪公司对「市场数据类工具」的心理价格带：**AED 500–2,000/月（$136–545）**
> $699 Agency 落在带子偏上 —— 不算离谱，**但必须在某个具体点上强过 Property Monitor 才卖得动**。

### 3.3 判据全过（首次）

| 判据（`2026-07-24-how-to-find-direction-founder-advice.md` 第 2 节） | 经纪公司 × 市场数据 |
|---|---|
| ① 这笔钱过去 90 天已经在流动吗 | ✅ **AED 500+/月，已在付** |
| ② 能否一周内手工交付一次 | ✅ 手工出一份定价报告即可 |
| ③ 有没有人替我开门 | ✅ 合伙人是持牌从业者 |

## 4. ⚠️ 这条证据推翻了本人前一轮的头号建议

**前一轮建议**（`2026-07-24-worst-case-plan-and-lead-tool-verdict.md` 第 3.A 节）：
> 「优先测开发商，卖 $999 市场情报报告。」

**被推翻的依据**：合伙人的开发商付费清单里 **没有市场情报**。
开发商买的是 **触达（硬广/门户流量广告）** 和 **线索管理（CRM）**，以及 **自建 3D 看房团队**。

| 修正 | 内容 |
|---|---|
| 开发商侧优先级 | **第一 → 第二** |
| 未完全否决的理由 | Property Monitor 仍将开发商列为客户，故非零；但按一线从业者说法非主科目 |
| 「自建 3D 看房团队」的读法 | 开发商在**买家侧销售物料**上确实花大钱（贵到自建）→ 但自建 = 能自己做 = 企业级长周期销售，**不适合当前处境** |
| 「CRM 系统」的读法 | 本产品有 CRM，但 `lt_clients` 全站 5 个客户 / 4 个经纪 → **不构成可信入口** |
| 「门户流量广告」 | 最大支出项，**无法竞争** |

> **元教训：桌面推理（「下行市场情报需求上升」）看起来三条路径收敛、可信度高，仍然被一句一手回答改写。**
> **一手证据的权重高于任何数量的二手推理。**

## 5. ⭐ 由此得到的最强假设（当前推荐方向）

### 5.1 拼图

```
经纪公司付 AED 500+/月给 Property Monitor 看数据
                    ↓  拿去干什么？
   二手市场 −42% 时，经纪最难的不是找买家，是【从业主手里拿到房源委托】
                    ↓  靠什么拿？
        拎着一份专业的定价分析去见业主（listing pitch）
                    ↓
Property Monitor 是测量师行血统：【给你数字，不给你能交到客户手上的成品】
```

### 5.2 假设

> **可卖的不是「数据」，是「拿数据自动生成一份能赢下房源委托的成品」。**
>
> - **数据层**：Property Monitor 已占据 + Dubizzle 集团背书 + 2014 年至今 → **打不过，不要打**
> - **成品交付层**：**空的**，且正好是本产品唯一造得出来、外部经纪也确实在看的东西
>   （`area_detail` 44 个外部登录用户 + 189 个匿名会话）

### 5.3 「显得专业」这句话的正确用法

| 说法 | 是不是预算科目 | 能否收钱 |
|---|---|---|
| 「让客户觉得比其他经纪专」 | ❌ 感受 | **没人为「显得专业」开支票** |
| **「多拿下一个房源委托」** | ✅ 收入 | **一单二手佣金 >> 一年软件费** |

**同一件事的两种说法。必须用后一种去卖。**

## 6. 下一步：四个问题（零代码）

问合伙人 + 3 个经纪公司经理：

1. **你们公司给 Property Monitor 付多少钱？几个人在用？**
2. **他们用它主要干什么？** → 若答案含「给业主报价 / 谈委托」→ **5.2 假设成立**
3. **⭐ 哪件事它做不了，你们只能用 Excel 或者靠问人？** → **答案就是产品**
4. **上一次你们公司为一个新工具付钱是什么时候，为什么？**

> **第 3 题的答案，比再写十份报告都值钱。**

**建议带实物去问**：用库里 DLD 数据做一份「给业主的房源定价委托报告」样张（指定楼盘即可代跑）。
**带着实物问，得到的答案比空口问真实得多**（同 `how-to-find-direction` 第 3.3 节）。
