# 实时带看「半分钟延迟」诊断 — 2026-07-13

**问题来源**:合伙人现场给 4 个新经纪演示实时带看,反馈「大概有半分钟左右延迟,是网络的问题吗?」

**结论先说**:**不是网络问题,也不是同步链路的问题**。实时同步实测端到端 161ms。
唯一能到「半分钟」量级的,是客户手机**点开分享链接到画面加载出来**的首屏时间 ——
在弱网下实测 16~20 秒,现场会场 WiFi 更差就是半分钟。**问题在首屏体积,不在实时性。**

---

## 一、实时同步链路:健康,洗清嫌疑

探针 `backend/scripts/probe-collab-latency.ts`(两条真实 WS 打生产,同一时钟):

| 测量项 | 结果 |
|---|---|
| WS 握手(TLS + upgrade,过 Cloudflare) | 379ms / 345ms |
| ping→pong 纯网络往返 | p50 **161ms** |
| **cam 帧 经纪→服务器→客户 端到端** | p50 **161ms** · max 170ms |
| 20Hz 连发 3 秒(和真实经纪端同频) | p50 161ms,**前 10 帧 161ms → 后 10 帧 161ms,零累积** |

端到端延迟 = 一个网络往返,一毫秒不多。20Hz 压 3 秒队列不堆积,说明服务端和链路
都吞得下真实带看的帧率。**代码里也不存在任何 30 秒量级的定时器**(同步 20–25Hz,
重连退避上限 10s,心跳 25s)。

## 二、真凶:客户端首屏 + 卫星瓦片

探针 `frontend/scripts/_probe-viewer-join.mjs`(真实 iPhone 型号 + 网络节流,
一个 presenter 顶住房间 20Hz 发 cam,量客户端从点链接到画面追上的每一段):

| 阶段 | 4G(20Mbps) | 弱网(1.5Mbps) |
|---|---|---|
| 点开链接 → 弹出「填称呼」 | 0.8s | **7.8s** |
| (客户手动填称呼、点进入) | — | — |
| 点「进入带看」→ WS 连上 | 0.9s | 0.5s |
| → 收到 sync(进房成功) | 1.0s | 0.8s |
| **→ 画面追完瓦片(看清经纪在看啥)** | **2.5s** | **8.6s** |
| 瓦片账单 | 59 个请求 · **4.8 MB** | 44 个请求 · 0.5 MB |

**弱网合计:7.8s(首屏)+ 填称呼的时间 + 8.6s(瓦片)≈ 16~20 秒起步。**
再叠加现场会场 WiFi 多人共享、真实手机 CPU 比模拟慢、卫星瓦片(Esri)本身重
—— **半分钟完全说得通**。

客户的主观体验是:点了链接 → 白屏好久 → 填名字 → 地图糊着/空着好久 → 才看到经纪在看哪。
他会把这整段都叫做「延迟」,但这跟经纪拖动地图后客户多久跟上(161ms)是两码事。

## 三、顺带发现:客户可能根本没进来

今天现场那批房间(`collab_rooms`),**大部分 `peak_participants = 1`** —— 只有经纪自己:

| code | 主持人 | 参与者峰值 |
|---|---|---|
| 53V97 | joe.liang | 2 ✅ |
| F82JU | joe.liang | 2 ✅ |
| EXBGA | catherineyan0226 | **1** |
| 87WB7 / VWAAC / QX8BH / FDRTR / … | shelldubai26 | **1** |

进房前有一道**「填个称呼才能进」的身份门**(`CollabIdentityGate`,留客户线索用的)。
现场演示时如果客户没填就退出了,房间里就只有经纪一个人 —— 经纪自己是看不出
「对方没进来」和「对方卡着」的区别的,两者在他眼里都是「怎么半天没反应」。

**这一条只是相关性,不是定论**,但值得跟合伙人核实:当时客户手机上到底停在哪一屏。

## 四、下一步

**必须先问清楚**「半分钟延迟」具体指哪个:

1. **客户点了链接半天进不来 / 地图白着** → 就是本报告的首屏问题,方向明确(见下)。
2. **客户已经在房里了,经纪拖地图,客户半分钟后才动** → 我们没能复现(实测 161ms),
   需要现场信息:当时几个人、什么网络、语音开着没。

如果是 ①,能做的优化(按性价比排序):

- **首屏 4.8MB 的瓦片是大头**。进房初期先上低清瓦片/矢量底图垫着,清晰卫星图后台
  再补 —— 客户先能看见「在哪」,再看清「长啥样」。
  ⚠️ 底图**必须**保持卫星(owner 已明确要求,见 memory `luna-tour-must-use-satellite`),
  这里说的是加载策略,不是换底图。
- 弱网下首屏 bundle 7.8s 才 DOMContentLoaded,值得单独查一次前端包体积。
- 身份门可以先放人进去看地图、再问称呼(把「填表」挪到不挡路的地方),
  但这会牺牲线索采集 —— 是产品取舍,得 owner 拍板。
