# Luna Tour 实现难度评估

> 日期:2026-05-30 · 配套 `docs/luna-tour-experience-spec.md`
> 结论:没有"做不出来"的模块;底层资产齐(voice/地图/数据/Gemini Live/投资计算都已成熟)。难度集中在**回放引擎的工程细致度** + **AI 脚本质量打磨**。

---

## 难度分三档

### 🟢 确定性体力活(知道怎么做,只是工时)
| 模块 | 难度 | 说明 |
|---|---|---|
| 数据层 + CRUD + RLS + `/v/:code` 公开页 | 低 | Supabase 现成 |
| 遥测 + lead_score + ❤️反馈 + "正在看"提醒 | 低 | 埋点 + 物化视图 + SSE |
| OG 动态卡 + 首帧烘焙 | 低中 | satori + 地图截图 |
| Stripe 订阅 + 配额门 | 低中 | 标准支付集成 |

### 🟡 工程密集(难但确定,可算工时)
| 模块 | 难度 | 关键点 |
|---|---|---|
| TimelineEngine 回放引擎(§4.3) | 中高 | 单时钟驱动音/相机/overlay 三轨 + 状态机 + seek/pause + 预加载;60fps、音画同步 |
| 地图命令式接口 + 电影运镜(§4.4) | 中 | 加 ref 不难;orbit/flyover 自写 rAF 插值;手机 3D pitch 性能 |
| 数据 overlay 动画(距离线/ROI count-up/辐射) | 中低但量大 | 数据现有 tools 已能产出,纯做动画化 |
| 切 Live 无缝(§4.6) | 中 | voice 全套已在,system instruction 参数化 + 暂停恢复衔接 + 同 voice |
| 经纪创作端(故事板 + AI代配) | 中 | 故事板编辑器是不小前端 |
| 预生成音频 + R2(§4.5) | 中 | 全新子系统(零 TTS-to-file/零 R2);MVP 可浏览器 TTS 兜底先跳过 |

### 🔴 真正瓶颈(不确定,需迭代)
1. **AI 脚本质量(§4.2)** — prompt + 结构化输出不难写;"排出不尬、有节奏、时间轴合理的脚本"是变量。跑通约 1 天,打磨到惊艳约 1–2 周。**最大赌注。**
2. **整体丝滑震撼感** — 运镜/音画同步/缓动/手机性能的总和,只能边做边调。

---

## 周期感(熟练全栈,诚实范围)
- Phase 0 心脏切片(写死数据,AI 脚本 + 基础回放,真机可看):**1–2 周**
- 可发布异步分享 MVP(全链路,暂用浏览器 TTS,不含订阅):**6–10 周**
- 完整产品(预生成音频 + 创作端 + 遥测 + 订阅 + 多语言):**3–4 个月**

---

## 建议
投入回放引擎那几周工程之前,先花 **1–2 天**拿真数据(2 套真房 + investment-calculator)实际让 Gemini 生成一份 TourScript v2,肉眼审脚本质量——花最小代价摸最大风险。
