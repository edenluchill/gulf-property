# Luna Tour 整体体验评估与修复（2026-07-12）

不再一个点一个点打地鼠。用 `frontend/scripts/_tour-audit.mjs` 把整场 tour 在
**手机 390×844 + 桌面 1440×900** 上逐帧录下来（每 2 秒一帧，同时打印相机状态和
字幕），先看清楚，再一次改完。

## 一、已修复并上线

| # | 问题 | 根因 | 处理 |
|---|------|------|------|
| 1 | 手机卡片占 **39% 屏幕**，而且**正好盖住项目本身**（pin 就在卡片正下方） | 卡片贴顶全宽 + 110px 大图 | 改成**底部横向小卡**（62px 缩略图 + 名字 + 价格 + 两个指标），占屏 **~10%** |
| 2 | 卡片被撑到 145px 高，项目名和价格被字幕吃掉 | `.lt-card-stats` 基类 `flex-wrap: wrap`，在窄栏里两个指标必然换行 | 手机上 `nowrap`；砍掉区域名/开发商/状态（旁白在说、地图在指） |
| 3 | 字幕糊在卡片上 | media query 里 `bottom` 写了**两处**，后面的 `76px` 覆盖了前面的 `96px` | 只保留末尾一条 `114px`，并在代码里注明别再写第二处 |
| 4 | 顶部章节名和经纪徽章重叠成一团 | 徽章 `left:64`，章节条 `94vw` 居中，390px 宽必然撞 | 手机上只留三段进度条，不显示章节名 |
| 5 | **弹远又弹近** | 跨项目 flyover 走 van Wijk 曲线会自动拉高再落下；跨半个迪拜就成了「弹一下」，中间几秒画面里没有任何信息 | 飞行硬上限 **2 秒**（`MAX_CAM_MS`） |
| 6 | **到了目的地还在转** | arrival 之后跟一个 orbit —— 镜头绕着一栋还没盖的楼转 | **orbit 整个丢弃**：客户已经到了，他要的是信息不是晕 |
| 7 | 开场「莫名其妙的平移」 | 欢迎页背后有一个 **60fps 无限自转循环**（`bearing += 0.05`） | 改成**一次性 jump 到剧本 intro 的建立镜头** |
| 8 | 几十个蓝色 POI 图标铺满屏幕，项目 pin 完全淹没 | 通用 POI 图层默认开 | tour 期间**关掉通用 POI 图层**。⚠️ 不是把配套藏起来：讲到「距地铁 0.91 公里」时，剧本用 `distance_line` **只画那一条线、只亮那一个站**。需要时才亮，亮的也只是那一个 |

**没动**（owner 明确要保留）：卫星底图、区域色块、3D 地标、地铁线。

已上线：后端 `quick-deploy` + 前端 CF Pages；`demo` 和 `demo-en` 两个剧本都已按新规则重新生成。

## 二、内容层 —— 也已修复并上线

| # | 问题 | 处理 |
|---|------|------|
| 9 | 旁白念原始数字：「购入价 **1800000** 迪拉姆」 | `humanizeNumbers()` 在 `validateTourScript` 里对所有 narration 跑一遍（字幕和 TTS 读同一个字符串）。**并且**在数据源把 5 年预测值抹到万位 —— 精确到个位就是假精度：「三百三十五万一千七百四十二」→「335 万」 |
| 10 | 在推销一套客户**买不到**的房：Palm Central 是 sold-out，AI 只能说「该项目目前处于售罄状态」，再硬拗成「顶奢海岛资产」 | 售罄项目在**选品阶段**拦掉（不是求 prompt 别说）。demo 换成 Palm Central 2（同一个岛，在售，21 个户型） |
| 11 | 「配套基建得分目前为 **0**」被当成事实播报 | 得分 0 = **我们一个 POI 都没查到**，不是「这地方配套差」。score 0 直接不进 prompt；prompt 也明写：**绝不把数据的缺席描述成关于房子的事实** |
| 12 | **户型信息全程缺席** —— 客户要买的就是户型 | 新增 `kind="homes"` 拍 + `unit_card` overlay，数据来自真实的 `project_unit_types`（面积/起价/户型图）。没有户型数据的项目**跳过这一拍**，不编 |

⚠️ `unit_card` overlay **故意不带任何数字** —— 只带 `property_id` + `focus_bedrooms`，
面积/价格/户型图全由前端从 snapshot 读。只要让模型往 overlay 里填数字它就会编
（`roi_card` 那次已经证明过了）。它能决定的只有「讲哪个项目、重点讲几房」。

### 一个反复踩的坑，值得单独记

**每把一张卡挪到底部，字幕就糊在它上面** —— 我栽了三次。根因是字幕的 `bottom` 是
写死的，而写死的值管不了「底下现在有没有卡、卡多高」。
最后用 `:has()` 让**字幕自己知道**底下有东西，不再靠每次手算一个新的 `bottom`。

## 三、原始的「还没修」清单（已全部完成）

布局和运镜现在干净了，但 tour 说的话还不行：

1. **旁白念原始数字**：「购入价 **1800000** 迪拉姆，预计 5 年后价值可达 **3351742** 迪拉姆」。
   人不这么说话。应该是「180 万」「335 万」。TTS 之前要做数字口语化。
2. **在推销一个售罄 + 配套得分 0 的项目**：Palm Central 的旁白原话是
   「该项目目前处于**售罄**状态，配套基建得分目前为 **0**」—— 然后硬拗成「顶奢海岛资产」。
   售罄的项目根本不该进 tour；得分 0 不该被念出来。这是选品和「什么该说、什么不该说」的规则缺失。
3. **户型信息全程缺席**。整场 tour 没有一句话、没有一个 overlay 讲户型 ——
   而客户真正要买的就是户型。这个缺口要靠 [Luna Tour Studio](../luna-tour-studio-spec.md) 里的
   户型 beat 补。

前两条可以直接在 `session-builder` / `tour-generator` 的提示词和选品规则里修；
第三条属于 Studio spec 的范围，等 owner review。
