# 功能规格:成交数据真相层(Transaction Truth)

> 即合伙人反馈中的"实时更新数据 / data.dubai"功能。本文档为独立、系统自洽的功能规格。
> 关联:`pinzos-design-spec.md` 的功能 B/C/D。
> 日期:2026-05-15 · 状态:待评审 · 服务对象:买房客户/投资人(免费)
> **已拍板决策:数据定时更新(每周同步),不做实时。** 架构图见 `pinzos-architecture.md` 第 2–3 节。

---

## 1. 一句话定义

把免费但脏乱、滞后、被挂牌价污染的官方 DLD 数据,清洗成**楼栋级别的成交真相 + 可解释的判断层**,回答买家真正的问题:"这套房现在到底值多少、真实净收益多少、能不能信"。

---

## 2. 为什么不是"实时数据"——基于调研的关键纠偏

合伙人原始设想是"获取 data.dubai 实时 API"。调研结论必须先纠正三点,否则做出来会承诺无法兑现:

1. **真·实时不存在,且不是痛点。** DLD 成交数据有 **4–8 周结构性滞后**(二手),期房更久——"3 月登记的成交是 1–2 月谈的"。这是登记机制决定的,任何产品都绕不过。把"实时"当卖点会被懂行的人当场拆穿。
2. **原始成交数据已经免费且公开。** Dubai Pulse 开放数据(约 150 万条,2004–2025,CSV+API)谁都能拿;DXBinteract 已免费提供逐笔成交。**单纯"展示成交数据"是红海,没有护城河。**
3. **真正没人解决的痛点是"解释层"。** 调研最强信号(r/dubai 高质量帖):买家看到门户 Dubai Hills ~31k AED/sqm、DLD ~12k AED/sqm,以为被骗 2 倍——真实原因(DLD 均价被旧期房交付价污染)**没有任何工具解释**。所有工具只给数字,没人回答"这对我这套房意味着什么"。

> **定位结论**:产品价值 = 清洗 + 解释 + 判断,不是"实时"。对外措辞用"**官方成交数据 + 数据时点透明标注**",不用"实时"。

### 数据源实测结论(2026-05-15 实测,已决定 design)

实测各官方端点可达性与可自动化性,结论如下:

| 端点 | 实测结果 | 可定时自动拉取? |
|---|---|---|
| `dubaipulse.gov.ae`(现有 import 代码所用) | TCP 连接超时(000) | ❌ 数据中心 IP 被封,服务器侧不可靠 |
| `data.dubai`(合伙人链接) | WAF "Request Rejected" | ❌ 登录制网页门户,非 API |
| `dldapp.dubailand.gov.ae`(Dubai REST) | 000 | ❌ 不可达 |
| `gateway.dubailand.gov.ae`(DLD 官方 Kong 网关) | 可达 | ✅ **主链路** |
| ├ `/tabu/transaction` 成交 | 401 需 API key | ✅ 注册取 key 后可用 |
| ├ `/ejarirentalindex/` 租金指数 | 401 需 API key | ✅ 同上 |
| ├ `/rest.mollak/servicecharge` 服务费 | 401 需 API key | ✅ 同上(净收益命门,官方有) |
| └ `/indexes-api` 开放 GraphQL | 200 但仅测试桩数据(`indexType:"testType"`) | ❌ 非生产,不可用 |
| `dxbinteract.com`(第三方) | 可达 | ⚠️ 非官方,仅作参照 |

**进一步核实(2026-05-15)——DLD 官方 API 网关不可行:**
- `api.dubailand.gov.ae` 是 DLD "Api Service Portal",但为**纯企业级**:**AED 30,000 + 5% VAT / 每 API / 每年**;强制要求**迪拜公司营业执照 + TRN 税号**;成交/服务费类还要求申请方本身是 RERA 批准银行或已注册 Ejari/Mollak 的 UAE 公司。无免费/沙箱档,不可个人注册。
- 该网关**不对第三方出售原始成交数据**,只提供 Ejari/Mollak/Trakheesi/经纪验证等操作类接口。→ **官方付费 API 路线放弃。**
- 合伙人提供的 data.dubai 账号是网页门户登录,**非 API 凭证**,无法用于程序化取数。

**对 design 的最终决定:**
1. **数据源 = Dubai Pulse 开放数据**(成交 `dld_transactions-open`、Ejari 租约、`dld_residential_sale_index-open`):免费、CSV + OAuth open-data API、无需 UAE 公司/Emirates ID。与 DXBinteract / Property Monitor / Reidin 的底层源相同,现有 import 代码方向正确。
2. **必须解决地理封锁**:`dubaipulse.gov.ae` 仅放行 UAE 网络,生产服务器在德国(Hetzner)实测不可达(000)。→ 抓取步骤走 **UAE 出口**(UAE 区域小 VM 或 UAE 代理/VPN),抓取后再回传主库。
3. **服务费(Mollak)无法自动化**:仅对 RERA 银行开放,免费源没有。→ 净收益功能降级:服务费来自楼书提取(功能 F)或人工补录,标注为"估算";净收益给"扣服务费前/后"两档。

**前置行动项(P0,阻塞本功能):**
- A. 注册 Dubai Pulse 账号,对 `dld_transactions-open` / 租约 / `dld_residential_sale_index-open` 发起 dataset "Grant" 申请,拿 open-data API key+secret(CSV 下载本身匿名,API key 走账号申请;开放 CSV 不需要 Emirates ID)。
- B. 准备 **UAE 出口**方案:UAE 区域云 VM(抓取专用,轻量)或 UAE 住宅/数据中心代理;评估成本与稳定性。
- C. 验证从 UAE 出口拉取的字段结构与更新频率,确认每周增量可行。

## 3. 目标用户与价值

| 用户 | 痛点(调研实证) | 本功能给的价值 |
|---|---|---|
| 首次/自住买家 | 看不懂门户价 vs DLD 价为何差一倍,怕被宰 | 楼栋级真实成交价 + "为什么有差距"的解释 |
| 收租投资人 | TruEstimate 收益率虚高(挂牌租/挂牌价),服务费吃掉净收益 | 真实净收益 = Ejari 实租 − 服务费 − 各项费用 |
| 期房投资人 | 期房比二手溢价 25–50%,无 like-for-like 对比 | 同楼/同区期房 vs 二手对比 + 溢价拆解 |
| 海外远程买家 | 开发商交付延期史无处可查,怕烂尾 | 开发商交付记录评分卡 |

**红线(与 design-spec 一致)**:买家端信任功能**永久免费、永不进付费墙**。商业化只发生在经纪人端(见 `pinzos-feature-agent-portal-spec.md`)。

## 4. 功能范围

### 4.1 纳入(按调研"需求×未被满足"排序)

1. **楼栋级真实成交价 + 差距解释器** ⭐核心
   - 任一楼栋/社区:近 N 月真实成交单价(中位数,非均价,避免被极值污染),成交量趋势。
   - **差距解释卡**:当门户在售价显著高于 DLD 时,自动拆解原因(新房 vs 二手、楼层、交付期、旧期房交付价污染均值),用中性可解释语言,不说"你被宰"。
2. **真实净收益** ⭐核心
   - 净收益率 = Ejari 实际登记租金 ÷ 真实成交价,再减去服务费(AED/sqft)与交易费用。
   - 与门户"挂牌租/挂牌价"的虚高收益率并列,标注差异。
   - 服务费数据来源:DLD Index / Mollak(楼栋级,需评估可获取性,见风险)。
3. **期房 vs 二手 like-for-like 对比**
   - 同楼优先,降级到同区同户型;给溢价率 + 拆解,不武断判好坏。
4. **开发商交付记录评分卡**
   - 历史项目数、平均交付延期、取消项目史。数据可由 `dld_transactions` 的项目首次登记 vs 承诺交付推导(精度有限,需标注口径)。
5. **数据时点透明标注**(诚实替代"实时")
   - 每个数字旁标注数据窗口与同步时间("基于 DLD 截至 2026-05-10 同步,二手登记通常滞后 4–8 周")。

### 4.2 明确不做(避免红海/伪需求)

- ❌ 宣称"实时"——改为"官方数据 + 时点标注"。
- ❌ 单纯逐笔成交流水浏览器——DXBinteract 已免费,无差异化。
- ❌ 通用"隐藏成本计算器"——每家中介都有,SEO 红海,无护城河。
- ❌ 自建挂牌门户/抢线索——见 agent-portal 文档的"陷阱"。

## 5. 功能要求

### 5.1 数据管线(已拍板:每周定时同步)

```
 Dubai Pulse 成交/Ejari 租约 ──┐  每周定时任务
 服务费 Mollak(待评估)      ──┘
        │
        ▼
 ① 拉取 ──► 记录数据截止日 data_vintage
        │
        ▼
 ② 清洗(护城河)──► 项目名归一化 · 去重 · 期房/二手分离 · 剔除关联交易
        │
        ▼
 ③ 计算 market-analytics ──► 中位数价 · 真实净收益 · 溢价拆解 · 区域分级
        │
        ▼
 ④ 落库 + 时点标注 ──► 指标表 + "数据截至 YYYY-MM-DD"
        │
        ▼
 功能 B 成交查询 · D 价格体检 · C 区域判断 · E 投资报告
```

- 数据源(实测+核实后最终确定):
  - **唯一可行源 = Dubai Pulse 开放数据**:`dld_transactions-open`(成交)、Ejari 租约、`dld_residential_sale_index-open`(住宅价格指数)。免费,CSV + open-data OAuth API。
  - **访问需经 UAE 出口**(UAE 区域 VM 或 UAE 代理)——dubaipulse.gov.ae 对非 UAE IP 拒连。
  - DLD 付费 API 网关(企业级 AED 30k/API/年)、data.dubai 网页门户、`/indexes-api` 测试桩——**均不采用**。
  - 服务费非自动化:来自功能 F 楼书提取或人工,标注估算。
- 同步:**每周定时增量,经 UAE 出口拉 Dubai Pulse(非实时,已拍板)**,每次记录数据截止日并对外标注。
- 清洗(护城河所在):开发商/项目名归一化、去重、期房 vs 二手分离、Ejari 租约与楼栋 join、剔除非市场化交易(赠与/关联方)。
- 统一收敛进 `market-analytics` service(与 design-spec 功能 C/D 共用,避免重复算)。

### 5.2 指标定义(必须可点开看口径)
- 成交价:**中位数优先**(均价仅作参考且标注"含期房交付价,可能偏高")。
- 净收益率:Ejari 实租中位数 ÷ 成交价中位数 − 服务费 − 费用;样本不足时显式提示"样本不足,不给结论"而非乱算。
- 任何判断/标签旁强制带:数据窗口、样本量、同步时间、口径说明(可点开)。

### 5.3 中性化框架(平衡买家信任与开发商=供给方)
- 溢价表述:"相对同区近 12 个月成交溢价 X%(可能反映新房/楼层/交付期/付款计划价值)"。
- 不出现"被宰/坑/骗"等对立词;给可解释因素而非道德判断。

## 6. 用户体验(用户旅程)

1. **入口**:项目详情页"价格体检"模块 + 独立的"成交查询"页(design-spec 功能 B)。
2. **价格体检模块**:一根水平标尺,标出区域成交区间(min–中位数–max)与本项目价位点,绿/黄/红 + 一句中性解释 + "为什么?"可展开看口径。
3. **差距解释卡**:当用户疑惑"门户价为何远高于 DLD",一键展开图文解释(本产品独有的解释层)。
4. **净收益**:收益率旁一个信息点,点开看"门户算法 vs 本产品算法"对照表。
5. **数据诚实**:页面底部固定"数据基于 DLD 截至 YYYY-MM-DD,二手登记通常滞后 4–8 周"。

体验原则:**少即是多**——不堆数字,每个数字配一句"这意味着什么"。

---

## 7. 成功指标

- 买家在"价格体检/差距解释卡"的展开率与停留时长(衡量解释层是否被需要)。
- 看过成交真相的用户 → 联系/收藏项目转化率(信任是否带来行动)。
- 客服/经纪反馈"客户用 DLD 质疑"的频次下降(产品是否提前解答了疑虑)。

## 8. 风险与待决

| 风险 | 说明 | 缓解 |
|---|---|---|
| 服务费无免费源 | Mollak 仅对 RERA 银行开放,免费数据集没有 | 服务费由功能 F 楼书提取/人工补录,标"估算";净收益给"扣服务费前/后"两档 |
| Dubai Pulse 地理封锁 | 仅放行 UAE 网络,德国服务器拒连(实测 000) | 抓取经 UAE 出口(UAE 区域 VM 或代理);主库在德国不变 |
| ~~DLD 官方 API~~ | 已核实:企业级 AED 30k/API/年 + 需迪拜执照,不卖原始成交 | 已结论:放弃官方付费 API |
| ~~data.dubai 链接~~ | 已实测:登录制网页门户非 API | 已结论:不作数据源,仅人工抽查 |
| 暴露在售项目偏贵 | 与开发商(供给方)关系张力 | 全程中性可解释措辞,给因素不给道德判断 |
| 数据清洗工作量 | 名称归一化/去重是真正护城河也是最大工作量 | 收敛进 `market-analytics` service,一次做好复用 |
| 开发商交付记录精度 | 由登记推导,口径有限 | 明确标注口径与局限,不夸大为"官方延期率" |
