# /developer/upload 布局重构方案对比 — 2026-06-12

## 现状问题

```
┌────────────────────────────────────────────────────────────────┐
│  智能 PDF 提取系统  ① 上传 ─ ② 提取 ─ ③ 审核 ─ ④ 提交            │
├──────────────────┬─────────────────────────────────────────────┤
│  📄 已上传文件     │  基本信息 → 日期 → 图片 → 户型 → 配套          │
│  [大上传虚线框]    │  → 付款 → 定价 → 检查清单 → 提交按钮           │
│  [AI 智能提取]    │                                              │
│  ✅ 提取完成      │  (从上到下五六屏,提交按钮在最底部)              │
│                  │                                              │
│  ← 上传完成后这列  │                                              │
│    就是死空间      │                                              │
└──────────────────┴─────────────────────────────────────────────┘
```

1. 左列(1/3 宽)在上传完成后没有任何作用,白占空间
2. 右列单条长表单,review 要滚五六屏;哪个区块有问题无从得知,只能滚着找
3. 提交按钮和检查清单在最底部,改完上面的字段看不到就绪状态变化

## 方案 1:分区工作台(推荐)

核心改变:
- 处理开始后,上传区收成**顶部一条细横幅**(文件名 + 进度条 + live 计数 + 暂停/取消)
- 表单拆成**左侧分区导航 + 右侧单区块显示**(Tab 式,不滚动)
- 导航每项带**完成状态点 + 数量徽标**(绿✓齐全 / 黄⚠有问题 / 数字实时跳动)
- **底部常驻提交栏**:readiness 摘要 chips + 已检查勾选 + 提交按钮,永远可见

```
处理中:
┌────────────────────────────────────────────────────────────────┐
│ 📄 Brokers Brief.pdf ▓▓▓▓▓▓░░ 64% · 📷12 🏠4 ✨9   [暂停][取消]  │
├──────────────┬─────────────────────────────────────────────────┤
│ ● 基本信息 ✓  │   (区块内容随提取实时填充,导航徽标实时跳动)          │
│ ● 图片 12 ↑  │                                                 │
│ ● 户型  4 ↑  │                                                 │
└──────────────┴─────────────────────────────────────────────────┘

review:
┌────────────────────────────────────────────────────────────────┐
│ 📄 Brokers Brief.pdf · 处理完成 ✓ 21s              [+ 补充文件]  │
├──────────────┬─────────────────────────────────────────────────┤
│  ● 基本信息 ✓ │   户型列表 (6)                                   │
│  ● 日期    ✓ │   [Type A 1BR ✓] [Type A 2BR ✓] [Type D ⚠缺价格] │
│  ● 图片 33 ✓ │   [Type B 3BR ✓] [Type A 4BR ✓] [Type C 4BR ✓]  │
│ →● 户型  6 ⚠ │                                                 │
│  ● 配套 22 ✓ │   ← 当前区块一屏内看完                            │
│  ● 付款    ✓ │                                                 │
│  ● 定价核对   │                                                 │
├──────────────┴─────────────────────────────────────────────────┤
│ ✓基本信息 ✓坐标 ⚠1户型缺价格     ☑ 已检查    [ 确认提交 ]         │
└────────────────────────────────────────────────────────────────┘
```

Review 动线:从上到下点一遍导航,✓ 的扫一眼,⚠ 的进去修,全程零滚动。
移动端:左导航变顶部横滑 chips,底栏堆叠。

## 方案 2:锚点导航 + 智能折叠(保守改良)

保留长表单,但齐全的区块**自动折叠成一行**(有问题的自动展开),左侧悬浮锚点
导航滚动联动,底部提交栏常驻。滚动从五六屏缩到一两屏。改动量最小。

```
┌──────────────┬─────────────────────────────────────────────────┐
│ 📄 文件 ✓(细条)│  ▶ 基本信息 · 已齐全 ✓            (折叠一行)     │
├──────────────┤  ▶ 日期与进度 ✓                    (折叠)        │
│  基本信息 ✓   │  ▼ 户型列表 6 个 · 1 个缺价格 ⚠     (自动展开)    │
│ →户型 ⚠      │  ▶ 付款计划 8 期 100% ✓            (折叠)        │
│  (滚动联动)   │  ▶ 提取定价核对                    (折叠)         │
├──────────────┴─────────────────────────────────────────────────┤
│ ⚠ 1 个户型缺价格                 ☑ 已检查    [ 确认提交 ]         │
└────────────────────────────────────────────────────────────────┘
```

## 方案 3:审核向导(分步)

review 拆成固定 4 步(①项目信息 → ②户型与图片 → ③付款定价 → ④提交),
每步一屏,带上一步/下一步。流程感最强、最防漏看;但熟手跳着改字段要切步骤。

```
┌────────────────────────────────────────────────────────────────┐
│ 📄 已处理 ✓   ①项目信息 ── ②户型与图片 ── ③付款定价 ── ④提交       │
├────────────────────────────────────────────────────────────────┤
│         第 ② 步:户型与图片(一屏聚焦)                             │
├────────────────────────────────────────────────────────────────┤
│ [← 上一步]                                    [下一步 →]        │
└────────────────────────────────────────────────────────────────┘
```

## 对比

| | 方案1 工作台 | 方案2 折叠 | 方案3 向导 |
|---|---|---|---|
| 消灭长滚动 | ✅ 彻底(零滚动) | 🟡 大幅缩短 | ✅ 彻底 |
| review 效率(熟手) | ✅ 最高 | 🟡 中 | ❌ 按步走 |
| 现代感 | ✅ 最强 | 🟡 一般 | ✅ 强 |
| 实时进度展示 | 顶条+导航徽标 | 细条+锚点徽标 | 顶条 |
| 改动量/风险 | 大 | 小 | 中 |

**推荐方案 1**(admin 熟手日常用);方案 3 适合将来开放开发商自助上传时再做。
共同收益:上传区收纳、底部常驻提交栏、状态可视化。
