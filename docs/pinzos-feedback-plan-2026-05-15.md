# Pinzos 优化反馈 — 需求拆解与优先级实施计划

- 日期: 2026-05-15
- 项目: gulf-property (Pinzos)
- 来源: 合伙人转达的开发商/客户优化建议
- 状态: 待评审

---

## 0. 总体判断

合伙人提出 6 条反馈 + 3 个核心功能。对照代码库现状,结论如下:

- **数据地基已就绪**: DLD 成交数据(约 1GB)已全量导入数据库(`dld_transactions` / `dld_rent_contracts` / `dubai_communities`),区域级指标(中位数单价、租金回报率 `rentalYield`、资本增值 `capitalAppreciation`)已算好并展示在地图热力图与语音助手中。
- **真正的缺口是"把现有数据产品化"**: 成交记录查询页、区域分级判断、期房 vs 成交对比、AI 分析报告 —— 即合伙人强调的 3 个主功能,数据有了但缺面向客户的查询/判断/报告层。
- **纯新建模块**: 经纪人订阅付费体系(目前只有 Supabase Auth,无角色/计费)、地图测距、卫星底图切换。

优先级原则: **先做低成本高感知的速赢 (P0) → 再做产品壁垒型核心功能 (P1) → 最后做依赖基建与商业决策的订阅体系 (P2)**。

## 1. 逐条反馈分析

### 反馈①: 卫星底图切换(去掉区域层,显示卫星+项目)

- **现状**: `frontend/src/components/MapViewMapLibre.tsx:29` 只有单一 `MAP_STYLE = 'https://basemaps.cartocdn.com/gl/voyager-nolabels-gl-style/style.json'`。区域层是 GeoJSON `area-fills` 多边形,已可通过 `showDubaiLayer` 控制。无卫星栅格源。
- **要做**:
  1. 增加卫星栅格 source(如 Esri World Imagery / Mapbox Satellite,需确认授权)。
  2. 地图加"底图切换"控件: 矢量底图 / 卫星底图。
  3. "区域层显隐"开关与底图切换解耦,卫星模式下默认隐藏区域填充、保留项目 pin。
- **工作量**: ~1 天
- **优先级**: **P0**
- **验收**: 切换按钮可在矢量/卫星间切换;卫星模式下仅显示卫星影像+项目 pin,区域多边形可独立开关。

### 反馈②: 按开发商显示项目 + 竞品对比 + 地图测距

- **现状**: `residential_projects` 表有 `developer` 字段;`MapPage.tsx` 已从 pins 派生开发商列表,`FilterDialog` 已支持按开发商过滤。**无**"我的项目"绑定关系,**无**测距工具。
- **要做**:
  - ②a: "开发商视图"模式 —— 登录开发商账号默认只显示自己项目;提供"添加竞品开发商对比"多选,叠加显示其它开发商项目(视觉区分颜色)。依赖: 开发商账号与项目的归属关系(与反馈⑤的角色系统相关,P0 阶段可先用简单 `developer` 字段匹配 + 开发商选择器代替正式账号绑定)。
  - ②b: 地图测距工具 —— 点击两点/多点显示直线距离(及可选驾车距离),独立小组件。
- **工作量**: ②a ~2 天(简化版,不含正式账号体系) / ②b ~1-2 天
- **优先级**: **P0**
- **验收**: 可选定"主开发商"只看其项目;可勾选竞品叠加对比;测距工具可量取地图任意两点距离并显示。

### 反馈③: data.dubai 实时成交数据 → 成交记录页 + 区域判断

- **现状**: 已集成 Dubai Pulse / DLD 公开数据集(`backend/src/db/dubai-analytics-schema.sql`, `import-dubai-analytics.ts`, `dubai-area-metrics.sql`)。区域指标函数 `get_dubai_area_metrics()` / `refresh_dubai_area_metrics()` 已有。**无**面向客户的成交记录查询页,**无**区域分级判断。
- **前置调研(必做)**: 合伙人给的 `data.dubai` 链接+账号(Pinzos.founder@gmail.com)需要先确认: 它是网页查询门户还是有可编程 API?这决定"实时"能否实现,以及是否需要替换/补充现有 DLD 数据源。**先调研再排期。**
- **③(1) 成交记录查询页**:
  - 筛选维度: 区域 / 项目 / 户型 / ready vs offplan / 单价 / 成交时间 / 中位数 / 均价 / 最高最低价 / 租金 / 收益率 / 资本回报率。
  - 与在售项目对比 → 风险判断(在售价 vs 区域成交中位数偏离度)。
  - 后端: 新增成交查询 API(基于 `dld_transactions` 聚合);前端: 新建 `TransactionsPage`。
  - **工作量**: ~6-8 天
- **③(2) 区域分级判断**:
  - 基于成交趋势/项目量/供应量,把区域分类: 成熟区 / 增长区 / 未来区 / 供应压力区。
  - 算法: 用已有 DLD 指标(成交量趋势、价格增长率、新供应量)定义分类规则引擎。
  - **工作量**: ~6 天(与"核心①"合并实现)
- **优先级**: **P1**(前置调研 P0/即办)
- **验收**: 客户可按多维度查询历史成交并与在售项目对比;每个区域有自动分级标签及依据说明。

### 反馈④: 楼书提取(户型/付款计划/价格)易错乱丢失 + 人工修正

- **现状**: LangGraph 多 agent 提取管线已完整(`backend/src/langgraph/`,含 `unit-detail-extractor` / `pricing-extractor` / `payment-plan-extractor`)。`AdminPropertyEditPage.tsx` 已能编辑 `unitTypes` 和 `paymentPlan`(部分人工修正能力存在),但缺"提取后审核闭环"和准确度优化。
- **要做**:
  1. 提取准确度优化: 针对户型↔付款计划↔价格错位问题,调整提取 agent 的提示词与结构化校验(交叉验证户型数与价格数对齐)。
  2. 人工修正闭环: 提取完成后进入"待审核"状态,审核界面并排显示 PDF 原文与提取结果,逐项确认/修改后才发布。
- **工作量**: ~6-8 天
- **优先级**: **P1**
- **验收**: 提取结果有置信度标记;低置信项高亮;审核界面可对照原文逐项修正后发布。

### 反馈⑤: 经纪人端口 + 免费试用 + 订阅付费

- **现状**: 仅 Supabase Auth(`backend/src/middleware/auth.ts`,有 `admin` 角色)。**无**经纪人角色、**无**订阅/计费/支付集成、**无**试用期逻辑。
- **要做**: 经纪人注册 → 14-30 天免费试用 → 订阅分层:
  - 299 AED/月(早鸟 199): 基于数据的 AI 区域分析、生成内容文案。
  - 999 AED/月(限 top 100): 优先线索分配、专属曝光、内容工具、项目对比报告。
  - 需要: 角色系统(agent/developer/admin)、订阅状态机、支付集成(迪拜可用 Stripe/Telr/Network)、试用倒计时、付费墙、线索分配逻辑。
- **工作量**: ~15-25 天(含支付基建)
- **优先级**: **P2**
- **关键依赖**: 必须先有"值得付费的内容"(即 P1 的 AI 报告/区域分析)上线后,再把它们作为付费墙卖点。先收费后没内容会损害口碑。需商业拍板定价与支付渠道。

### 反馈⑥: 首页同时显示中位数/租金回报率/增值率 + 区域名

- **现状**: 指标已存在并以热力图叠加显示(`MapViewMapLibre.tsx` metric overlay)。问题是数值标签未同时带区域名。
- **要做**: 区域标签层同时渲染"区域名 + 当前选中指标值";或区域卡片/tooltip 同时展示三项指标(中位数、租金回报率、增值率)+ 区域名。
- **工作量**: ~1 天
- **优先级**: **P0**
- **验收**: 地图区域标签/卡片同时显示区域名与关键指标,无需点击即可识别。

## 2. 三个核心功能(合伙人战略重点)

这三个是产品壁垒,共用同一套 DLD 指标层。建议统一抽出 `market-analytics` service,避免在成交页/区域判断/对比/报告里重复算逻辑。

### 核心①: 地区区域判断 + 区域间对比 → 指导用户选择

- 等同反馈③(2) + 反馈⑥的延伸。区域分级 + 两区域并排对比(指标雷达/表格)+ 文字化判断结论。
- **工作量**: ~6 天 | **优先级 P1**

### 核心②: 成交单价 vs 期房单价对比 + 同区域期房对比

- 数据两边都有(`residential_projects` 在售价 + `dld_transactions` 成交价)。需对接计算偏离度并 UI 呈现,给出"溢价/折价"判断指导。
- **工作量**: ~4 天 | **优先级 P1**

### 核心③: AI 买房/成交分析报告

- 场景: 投资(增值/收租/兼具)、自住、自住兼投资 → 帮客户选区域/项目/户型。
- 逻辑示例: 选租金回报 8% 的区域/项目,或资本增值率 10% 的区域/项目;结合项目付款计划做增值预测(如付款计划 4 年付 60%,区域年增值 15%,4 年可能实现约 100% 资本收益)。
- **现状**: `investment-calculator.ts` 已有 5 年投资测算(`calculateInvestment5yr`、`calculatePaybackYears`),语音助手 Luna 已能口头分析。缺: 结构化报告生成 + 多场景策略逻辑 + 可导出文档(PDF)。
- **工作量**: ~8-10 天 | **优先级 P1**

## 4. 分阶段路线图

### 阶段 1 — 速赢包(约 1 周, P0)
卫星底图 + 首页区域名 + 开发商视图 + 测距 + data.dubai 调研。
目的: 低成本、开发商立刻能感知,适合下次演示。

### 阶段 2 — 市场分析核心(约 3-4 周, P1)
按"数据→判断→报告"顺序: 成交记录页 → 区域分级判断+对比 → 期房 vs 成交对比 → AI 分析报告。
统一抽 `market-analytics` service。

### 阶段 3 — 内容质量(约 1.5 周, P1,可与阶段 2 并行)
楼书提取准确度优化 + 人工修正审核闭环。

### 阶段 4 — 商业化(约 3-5 周, P2,阶段 2 完成后启动)
经纪人角色系统 + 试用 + 订阅分层 + 支付集成 + 付费墙(把阶段 2/3 成果作为卖点)。

## 5. 风险与待决项

1. **data.dubai 数据源**: 链接+账号需先确认是否有可编程 API。若仅网页查询,"实时"目标需调整(继续用 DLD 定期刷新),并评估抓取合规性。**阻塞 ③ 排期。**
2. **卫星底图授权**: Esri/Mapbox 卫星瓦片有授权与配额限制,需确认商用条款。
3. **订阅定价与支付渠道**: 299/199/999 AED 定价、支付渠道(迪拜 Stripe/Telr/Network International)需商业拍板。
4. **开发商账号归属**: 反馈② 完整版依赖反馈⑤ 的角色系统;P0 阶段先用简化匹配,正式绑定放阶段 4。
5. **不要先于内容上线收费**: ⑤ 必须在 P1 AI 报告/区域分析成型后才有付费价值。
