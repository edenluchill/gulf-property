# Pinzos 优化反馈 — 详细设计规格 (Design Spec)

- 日期: 2026-05-15
- 项目: gulf-property (Pinzos)
- 性质: 现有项目增强的设计规格,以"客户价值验证"为核心
- 状态: 待 review(含 4 项需合伙人拍板的设计调整)

---

## 0. 核心方法论:每个功能必须回答三个问题

1. **服务谁?**(买房客户 / 开发商 / 经纪人 —— 经常被混淆)
2. **对买房客户真的有用吗?**(批判性验证,允许否定合伙人的原想法)
3. **体验是否够好?**(用户旅程 / 界面设计)

> 关键洞察:合伙人反馈把"开发商用着方便"与"对买家有价值"混在了一起。这两者有时冲突。本设计以**买家信任为地基**,凡是利于开发商但损害买家信任的,一律做成"模式开关",不做默认。

---

## 1. 用户角色定义

| 角色 | 描述 | 核心诉求 | 付费? |
|---|---|---|---|
| 买房客户/投资人 | 终端购房者 | 不被坑、看懂值不值、有人帮决策 | 否(免费) |
| 开发商 | 上传楼书、展示项目 | 体面展示、对比竞品 | 间接(供给方) |
| 经纪人 | 中介 | 用数据说服客户、拿线索 | 是(订阅) |

设计红线:买家端核心信任功能(成交记录、期房对比、区域判断)**永久免费、永不进付费墙**。

---

## 2. 设计原则

- **数据可溯源**:任何判断/标签旁必须可点开看"依据 + 数据出处 + 时间窗口"。
- **中性措辞**:涉及"贵/便宜/好/差"用可解释的中性表达,不制造对立。
- **不过度承诺**:所有未来预测给区间(保守/中性/乐观)+ 免责声明,不给单一保证数字。
- **复用现有能力**:DLD 指标层、investment-calculator、语音助手 Luna 已存在,新功能在其上构建。
- **模式而非默认**:利于单一角色的视图(如开发商专属视图)做成可切换模式。

## 3. 七大功能详细设计

---

### 功能 A:地图体验升级

#### A1. 卫星底图切换
- **服务谁**:买家(主) + 开发商
- **客户价值验证**:✅ 真有用。迪拜购房高频痛点是"渲染图很美,实际周边是沙漠/工地/烂尾"。卫星影像让买家亲眼核实选址环境,降低决策恐惧。
- **功能要求**:
  - 新增卫星栅格 source(Esri World Imagery 或 Mapbox Satellite,需确认商用授权与配额)。
  - 地图右上角"底图切换"控件:矢量(默认)/ 卫星。
  - "区域填充层"显隐与底图切换**解耦**:卫星模式默认隐藏区域多边形、保留项目 pin 与标签,可手动再开。
- **UX**:单按钮两态切换,切换有平滑过渡;卫星模式下 pin 描白边保证可读。
- **验收**:可在矢量/卫星间切换;卫星模式默认仅显影像+pin;区域层可独立开关;移动端可用。

#### A2. 开发商展示模式 + 竞品对比
- **服务谁**:开发商(主)。**对买家是减分项**(选择变少)。
- **客户价值验证**:⚠️ 调整。对买家不利,故:
  - **绝不做成买家端默认**。买家端永远显示全部项目。
  - 仅作为**开发商登录后的可选"演示模式"**:默认只显示本开发商项目,可勾选 N 个竞品开发商叠加(不同颜色),用于销售对比。
- **功能要求**:开发商账号 → 项目归属关系(P0 阶段用 `developer` 字段简化匹配,正式绑定随功能 G 的角色系统);模式 toggle;竞品多选器;叠加项目颜色区分 + 图例。
- **UX**:登录开发商账号后顶部出现"演示模式"开关;开启后侧栏出现"+ 添加竞品对比"。
- **验收**:买家端不受影响;开发商可只看自己+叠加竞品;非开发商账号不出现此模式。

#### A3. 地图测距工具
- **服务谁**:买家 + 开发商
- **客户价值验证**:✅ 真有用且低成本。"项目到地铁/海滩/学校多远"是买家高频问题,目前需自己估。
- **功能要求**:地图工具栏测距图标;点击落点连线,实时显示累计直线距离(km);可多段;再次点击图标或 Esc 退出/清除。可选增强:显示到选中项目的距离。
- **UX**:轻量、即点即用,不弹窗;距离标签贴在线段中点。
- **验收**:可量取任意两点/多点距离,数值正确,移动端可触控。

### 功能 B:成交记录查询页(信任锚点)⭐⭐

- **服务谁**:买家(主)、经纪人、间接利好平台公信力
- **客户价值验证**:✅✅ **本产品最该做的功能**。迪拜买家对期房虚高价极度警惕;政府 DLD 真实成交数据 = 无法反驳的第三方背书。数据已全量在库(`dld_transactions` / `dld_rent_contracts`),只差面向客户的查询层。
- **风险与中性化设计**:它会暴露部分在售项目高于真实成交价 → 与"开发商是供给方"有张力。措辞用:"该项目单价相对同区近 12 个月成交**溢价 X%**(可能反映新房、楼层、精装、交付时间差异)"——给出可解释因素,而非"你被宰了"。
- **功能要求**:
  - 筛选维度:区域、项目、户型、ready vs offplan、成交时间范围、价格区间。
  - 展示指标:成交中位数单价、均价、最高/最低、成交量(趋势图)、平均面积、租金、租金收益率、(可选)资本回报率。
  - "与在售对比":选定一个平台在售项目,一键拉同区/同户型成交基准,显示溢价/折价率及解释。
  - 后端:基于 `dld_transactions` 的聚合查询 API(支持分页、多维筛选)。
  - 前端:新建 `TransactionsPage`。
- **UX(用户旅程)**:进入页 → 像"迪拜房价真相搜索引擎":顶部搜索/筛选条 → 结果区为指标卡 + 成交趋势折线 + 可展开明细表 → "和我关注的项目比一比"按钮 → 弹出对比条(标尺可视化)。
- **验收**:多维筛选准确;指标与官方数据一致;对比功能给出溢价率与中性解释;响应式;查询 < 2s。

### 功能 C:区域智能判断与对比 ⭐⭐

- **服务谁**:买家(主)
- **客户价值验证**:✅ 高价值——"我到底该买哪个区"是买家最大痛点。但 ⚠️ **风险最高**:把区域标成"供应压力区"是重论断,错了会同时得罪买家和开发商。
- **对原想法的设计调整**:
  1. 分类**方法论必须透明可点开**(例:"供应压力区 = 未来 24 个月新增供应 ≥ 现有存量 40% 且近 12 个月价格增速 < 区域均值")。
  2. 措辞**中性偏保守**,标签旁永远带数据窗口与时间。
  3. 提供**双视角解读**:同一标签对"投资"和"自住"含义不同(供应压力区 → 投资风险高 / 自住议价空间大)。
- **功能要求**:
  - 分类引擎:基于已有 DLD 指标(成交量趋势、价格 CAGR、新增供应量、租金收益率)的规则引擎,输出 4 类标签:成熟区 / 增长区 / 未来区 / 供应压力区。
  - 每个区域:标签 + "为什么?"展开(指标明细 + 阈值 + 数据时间)。
  - 区域对比:任意两区并排,指标表 + 雷达图 + 一句话结论(含双视角)。
  - 抽取统一 `market-analytics` service,供 B/C/D/E 复用。
- **UX**:区域详情面板顶部彩色标签 chip + "为什么?"可展开;对比入口在区域面板"对比"按钮 → 左右双栏页。
- **验收**:每区有标签且依据可查;两区对比清晰;措辞中性;方法论文档化。

---

### 功能 D:期房 vs 成交单价对比(防坑)⭐⭐

- **服务谁**:买家(主)
- **客户价值验证**:✅✅ 买家最强的"防被坑"工具,强差异化。与 B 同样的政治敏感性,采用相同中性框架:把溢价拆解为可解释因素(新房 vs 二手、楼层、交付时间、付款计划的资金时间价值)。
- **功能要求**:
  - 对任一在售期房项目,自动匹配同区/同户型近 12 个月二手成交价。
  - 计算溢价率,判定"合理 / 偏高 / 偏低",并列出可能解释因素。
  - 与功能 C 一致,逻辑收敛进 `market-analytics` service。
- **UX**:项目详情页新增"价格体检"模块:一根水平标尺,标出区域成交区间(min–median–max)与本项目价位点,绿/黄/红 + 一句中性解释。
- **验收**:匹配逻辑合理(同区同户型优先,降级到同区);判定有解释;无可比成交时明确告知"样本不足"而非乱判。

---

### 功能 E:AI 买房决策报告 ⭐⭐

- **服务谁**:买家(主)
- **客户价值验证**:✅ 高价值(多数买家无能力自行测算)。⚠️ **最大风险:过度承诺**。"4 年付 60%、年增 15%、4 年回报 100%"若写死,房价不及预期时严重反噬信任、甚至纠纷。
- **关键设计调整**:
  1. 所有预测给**区间(保守/中性/乐观)**,不给单一数字。
  2. 明确标注**假设 + 免责**("基于过去 X 年 DLD 数据,不构成投资保证")。
  3. 报告定位 = "**结构化决策框架 + 数据支撑**",非"稳赚承诺"。
- **功能要求**:
  - 输入:目标(投资-增值 / 投资-收租 / 投资-兼具 / 自住 / 自住兼投资)+ 预算 + 偏好(户型/区域倾向/持有年限)。
  - 输出报告章节:推荐区域(附功能 C 标签与理由)→ 推荐项目(附功能 D 价格体检)→ 推荐户型 → 资金计划(结合项目付款计划的现金流时间表)→ 收益区间预测(保守/中性/乐观三档,基于 `calculateInvestment5yr`)→ 风险提示与假设说明。
  - 可导出 PDF;语音助手 Luna 可朗读讲解(复用现有 5 年测算与 Luna 工具)。
- **UX**:3 步问卷(目标 → 预算/偏好 → 生成)→ 在线报告页 + "下载 PDF" + "让 Luna 给我讲讲"。
- **验收**:报告各章节数据来自 B/C/D 同源;预测为三档区间;含免责;PDF 排版可用;Luna 能基于报告对话。

---

### 功能 F:楼书提取质量 + 人工修正(地基)⭐⭐

- **服务谁**:间接服务所有人——它是 B/C/D/E 的**数据地基**。
- **客户价值验证**:✅✅ 若户型/价格/付款计划提取错,上面所有"信任"功能建在沙子上;客户看到错价 → 信任瞬间崩塌。**优先级应与功能 B 同级,不可后置。**
- **功能要求**:
  - 提取准确度优化:针对"户型↔付款计划↔价格错位",强化 agent 提示词 + 结构化交叉校验(户型数与价格条目对齐;付款计划比例之和=100% 否则报警)。
  - 人工修正闭环:提取完成 → "待审核"态;审核界面**并排显示 PDF 原页 vs 提取结果**;低置信字段高亮;逐项确认/改后才"发布";复用并扩展 `AdminPropertyEditPage`(已能改 unitTypes / paymentPlan)。
- **UX**:审核队列列表 → 进入单条:左 PDF 预览、右结构化表单,问题项红框 + 提示,底部"全部确认并发布"。
- **验收**:每个提取字段带置信度;校验规则触发报警;未审核项不对外展示;审核后数据正确入库。

---

### 功能 G:经纪人订阅商业化

- **服务谁**:经纪人 + 平台营收。**对买家零价值。**
- **客户价值验证**:❌ 对买家无价值,纯变现。**设计红线**:不得把买家端信任功能(B/C/D)放进付费墙;订阅卖的是经纪人**生产力工具**,不是阉割买家体验。
- **功能要求**:
  - 角色系统:agent / developer / admin(扩展现有 Supabase Auth)。
  - 试用:注册即 14–30 天免费试用,倒计时与到期降级。
  - 分层:299 AED/月(早鸟 199)= 基于数据的 AI 区域分析 + 内容文案生成;999 AED/月(限 top 100)= 优先线索分配 + 专属曝光 + 内容工具 + 项目对比报告。
  - 支付集成:迪拜可用渠道(Stripe / Telr / Network International)——需商业拍板。
  - 付费墙逻辑:仅作用于"经纪人工具",买家功能不受限。
- **依赖**:必须在 B/C/D/E 成型后启动(否则没有"值得付费的内容"可卖)。
- **验收**:试用→订阅→到期流程完整;买家端不受付费墙影响;支付与发票合规。

## 4. 基于客户价值重新排序(已不同于初版)

排序首要依据 = **客户价值 × 是否地基**。

| 顺序 | 功能 | 理由 |
|---|---|---|
| P0 速赢 | A1 卫星底图 / 首页区域名+指标 / A3 测距 | 便宜、买家直接受益、可演示 |
| **P1-地基** | **F 提取质量+人工修正(提前!)** | 数据不准则 B/C/D/E 全部不可信 |
| P1-信任① | B 成交记录查询页 | 第三方数据信任锚点 |
| P1-信任② | D 期房 vs 成交对比 | 防坑差异化 |
| P1-信任③ | C 区域智能判断与对比 | 选区决策,风险最高需谨慎 |
| P1-决策 | E AI 买房决策报告 | 复用 B/C/D 数据 |
| P2-商业化 | G 经纪人订阅 + A2 开发商模式 | 依赖角色系统与基建,最后做 |

> 与初版最大差异:**功能 F 从"靠后"提到"P1 第一位"**——因为它是其余信任功能的地基。

## 5. 待合伙人 review 的 4 项设计调整(需拍板)

1. **开发商视图不做默认**:仅作开发商登录后的"演示模式",买家端永远全量显示。
2. **功能 F(提取质量)优先级提前**至与成交记录同级——数据不准会毁掉所有信任功能。
3. **AI 报告只给区间 + 免责**,不给"稳赚"单一数字——规避法律与信任风险。
4. **成交/期房对比用中性可解释措辞**,不说"你被宰了"——平衡买家信任与开发商(供给方)关系。
