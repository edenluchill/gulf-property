她回信的原文

Yaroslava Bursak · 2026-07-29 05:48

原句类型
"Your program is very good!"赞美 —— 让你感觉良好，信息量 0
"Just update it more"废话 —— 不指向任何具体的一次
"Would be great if we can type an area…"点子 + 未来假设 —— 客户在替你做产品设计
"Can't find many off plan projects"唯一一句事实 她真实的处境
而我们的回应正是书里点名的错误动作

把点子当需求，做掉，然后回信说「做好了」。
正确动作是往下挖：「你上次找不到的是哪个盘？找不到之后你怎么办的？」

为什么必然是这个结果

那封群发信问的是「Overall, how has the platform been for you so far?」和「Is there something you'd like us to improve?」—— 两个都是在请求意见。按妈妈测试，请求意见就只会得到意见。

16 封信、1 封回信、0 条事实。
这不是运气差，这是问法的必然产出。
但邮件不是没用

发信后 14 天内 9/16 回访了站点（56%）。
他们不是不理你 —— 是那封信没给他们任何说话的理由。

核心

那句唯一的事实，我们只做了一半

而且承诺的那一半没兑现。

我们把她那句话拆成两半：

  • 搜索框（"type an area and it brings you there"）→ ✅ 做了
  • 覆盖（"can't find many off plan projects"）→ 回信承诺「this week from 40+ to 100+」

结论

三个被推翻的假设

假设判定
「没人回我 = 没需求」推翻 56% 回访。有需求，只是没人有话说
「产品坏了把她挡出去」部分 8/07 成立，8/14 已不成立。bug 已修
「不知道客户要什么」推翻 她说了。我们做了一半，另一半承诺了没做。
不是缺客户，是欠客户。

而我们这 20 天在做的是：Luna 语音质量、tour 运镜、健康度面板、派单、开发商验证 ——
没有一件是她要的那件。
方案

三个动作，本周内

「去联系客户」这个结论 7-28 写过、8-11 写过、今天 v1 又写过。前两次都没执行。所以这版每个动作都带「完成的证据长什么样」，而不是「去做 X」。

动作 01 · 还债

楼盘 55 → 100+

唯一一件「客户明确要求 + 我们明确承诺 + 我们没做到」的事。不需要猜需求，不需要访谈验证 —— 这是还债不是赌。

  • 这是运营工作不是开发工作 —— 楼书上传管线早就有（worker + R2 + AI 抽取）。缺的是把楼书灌进去的人工。
  • 完成标志：residential_projects ≥ 100，区域覆盖 ≥ 50。
动作 02 · 第一次真正的通话

不是邮件 —— 电话或当面

邮件问意见的路已经实测走死（16 封 → 1 回信 → 0 条事实）。不要再发第四封群发信。第一个人选：Yaroslava —— 唯一付过钱、8/14 还回来过、我们欠她一个交付。

开场：不问意见，先还债

「你 7 月说找不到很多期房盘 —— 那条我当时答应你一周内加到 100+，没做到，拖到今天。现在补上了（55 → N 个）。能不能占你 15 分钟，我想搞清楚一件事：你当时是在找哪个具体的盘？没找到之后你是怎么办的？」

  • 关键区别：它承认了一件她亲身经历过、而你能证明的事，并且带着交付物去，不是带着问题去。
  • 完成标志：通话记录 + 填满四力表七格（推力/拉力/焦虑/惯性/事件一/事件二/解雇了谁）。
